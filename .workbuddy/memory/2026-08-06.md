# 2026-08-06 项目规划：体脂秤 Android App（苏格拉底式 Q&A）

## 背景
参考开源项目 maoziban/smart-body-scale-android（专对接蚂蚁阿福 AFU 体脂秤）。
目标：做一个精简版，替换"功能繁多"的原版连接软件。

## Round 1 已锁定
- 硬件：蚂蚁阿福同款 → 直接复用其 BLE 协议（GATT / FFB2 特征 / 魔数 0xAC / 20 字节报文 / BIA 解析），不自研。
- 意图：精简版替换原版连接软件（产品化做减法，非练手）。
- 用户：一家多人共用一台秤 → 多成员家庭管理是核心功能，±7kg 动态权重匹配保留。

## Round 2 已锁定
- 架构：v1 **纯本地**（Room，多成员档案存本机），云同步明确留到 v2 以后。
- 功能焦点：**专注于"测量"与"最终结果"**，砍掉冗余（社交/多余设置/花哨仪表盘等）。
- 指标深度：**全量约 8 项指标**（体重/体脂率/BMI/水分/肌肉量/蛋白质/骨量/内脏脂肪等）都要，但要体现在"结果页"而非堆满首页。

## Round 3 已锁定
- 起点：**从零新建 + 跨平台（一次开发多端部署）**，仅借鉴开源项目的蓝牙数据处理方法（20字节报文解析 + BIA 算法），不自 fork、不自研协议。
- 运行环境：**minSdk = Android 9 (API 28)**；需处理 Android 9–11 的定位权限扫描 + 12+ 的 neverForLocation 两条路径。
- 设计语言：**Material 3 Expressive**；Android 端支持动态主题色（monet/dynamic color），其他平台支持自由设置主题色。

## Round 4 已锁定
- 框架：**Flutter (Dart)**（非 CMP）。开源的报文解析 / BIA 算法移植为 Dart 共享层。
- v1 目标端：**Android + Windows**（不含 iOS）。
- UI：**共享一套 UI**，Material 3 Expressive，**自适应布局（任意屏幕尺寸适配）**。
- BLE：Flutter 侧建议 flutter_reactive_ble（Android 9–11 定位权限 + 12+ neverForLocation；Windows BLE 是否 v1 接入待定）。
- 存储/状态：Round 5 确认（建议 drift[SQLite 跨端] + Riverpod）。

## Round 5 已锁定
- Windows 同步：用户希望 Windows 同步 Android 数据。但 Round 2 定"v1 纯本地、云同步留 v2" → 采用**本地传输式同步**（导出/导入备份 or 局域网传输），不引入云端。机制 M5 前与用户最终确认（OPEN）。
- MVP 范围：**M0+M1+M2+M3+M4+M5 全包含**（历史记录进 MVP），M6 为打磨/Windows 联调。
- 存储/状态库：**drift (SQLite 跨端) + Riverpod**（用户无偏好，用推荐）。
